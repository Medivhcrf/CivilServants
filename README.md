## 这个库在解决什么问题

申论不是作文比赛，是**材料信息处理考试**；阅卷按**采分点**给分，写到就给，写不到就不给，文采不加分。

核心主张：

| 主张 | 含义 |
| --- | --- |
| **要点抄材料，骨架自己搭** | 除大作文外，所有题型都是"摘点重组"，不是自由发挥；能概括，不能替换 |
| **一句一勾** | 按句号分号切句，逐句画勾，防止漏掉段落后半截 |
| **字数实测** | 字数不足就是漏点；超格直接扣分。写完先数字数 |
| **正反两层要对称** | 有"只算眼前账，食堂难以为继"，就必须有"算长远账，需多方发力" |
| **问什么答什么** | 问"困难"只答困难，材料里的做法段抄上去就是废字 |

## 详解标准（九步法）

每道题的解析都必须做满九步，**不得压缩成"给答案 + 说几个要点"**：

> 审题 → 逐段定功能 → 标点切分逐句找点 → 重新排队 → 成文（**实测字数**）→ 逐句拆解（**含材料出处**）→ 反面教材（**含估分**）→ 可迁移公式 → 布置同构新题

三条质量红线：

1. **答案字数必须实测**（跑脚本数），不许估
2. **正反两层必须对称**
3. **每个采分点、每个漏点都必须指出材料出处**（第几段第几句）

## 图解课件

`第2课-综合分析-图解.html` 是一个**单文件自包含**的可交互课件，固定六色语义：

| 颜色 | 含义 |
| --- | --- |
| 灰 | 背景 / 引子 |
| 蓝 | 意义 / 价值 |
| 红 | 问题 / 危害 |
| 绿 | 做法 / 对策 |
| 紫 | 观点 / 结论 |
| 琥珀 | 释义 |

颜色是语义，不是装饰——目的是让读者读材料时形成条件反射。

课件交付前必须通过校验：

```bash
python3 skill/scripts/check_diagram.py 申论/第2课-综合分析-图解.html
```

校验项：`data-src` 引用完整性、HTML 标签平衡、答案块与注释块数量一致、**「考场版」与「逐句注释版」逐字一致**、字数实测。

## 如何更新站点

改完 `申论/` 或 `skill/references/` 里的 Markdown 后，跑一条命令即可：

```bash
./tools/publish.sh "更新第3课内容"
```

它会依次完成：**构建 `docs/` → 推送到 `main` → 同步到 `gh-pages` 分支**（GitHub Pages 从后者发布，约 30 秒后生效）。

只构建不发布：

```bash
python3 tools/build_site.py     # 产物在 docs/
```

新增一份资料，只要在 `tools/build_site.py` 顶部的 `PAGES` 列表里加一行即可自动出桌面版和手机版。
